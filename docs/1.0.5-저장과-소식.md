# 1.0.5 저장 안정화와 소식 메뉴

개발 버전은 1.0.5, Android versionCode는 13입니다(12는 비공개 테스트에 먼저 올린 빌드). 이 문서는 배포 완료 기록이 아닙니다.

## 저장 변경

- 기존 저장 키에는 1.0.4도 읽을 수 있는 게임 본문을 유지하고, `_journal_v1` 키에 마지막 클라우드 리비전과 미전송 여부를 보관합니다. 두 항목의 본문이 다르면 구버전의 변경 또는 쓰기 중단으로 보고 기준 리비전을 신뢰하지 않습니다.
- 클라우드 리비전이 같으면 미전송 진행도를 업로드한 뒤 이어갑니다.
- 다른 기기의 저장과 충돌하거나 구버전 로컬 저장의 기준을 확인할 수 없으면 사용자가 선택합니다. 선택 전 로컬 원본은 계정 키 뒤의 `_recovery` 항목에 보관하며, 클라우드 덮어쓰기는 서버 백업 및 리비전 검사를 거칩니다.
- 처음 실행할 때 계정 저장을 확인하지 못하면 플레이를 막고 재시도를 안내합니다. 이미 플레이 중 발생한 네트워크 오류는 로컬 기록을 유지합니다.
- 신규 계정은 게임을 먼저 저장하고 프로필을 생성합니다. 구버전에서 프로필만 생성된 계정은 서버가 게임 진행 이력이 없는 것으로 확인한 경우 초기 저장을 재시도합니다.
- 클라이언트와 서버가 연못·코이·유전 정보의 동일한 구조 검사를 사용합니다. 필수 데이터가 손상되면 정상 백업 복구를 시도합니다.
- 새 게임 초기화는 대기 중인 저장을 마친 뒤 수행하고, 실패 시 기존 로컬 진행도를 지우지 않습니다.
- 모바일 플레이 중 기기에는 2초 간격으로 저장하고, 재화·구매·번식·판매·업적 등의 중요한 변화는 상태 반영 직후 저장합니다. 서버에는 중요한 변화 후 보통 2~4초 내 전송하고, 수질 등의 변화는 60초 주기로 보냅니다. 실제 전송 시점은 앱 실행 상태와 네트워크에 따라 달라집니다.
- 앱이 숨겨지거나 페이지가 종료될 때 기기에 먼저 기록하고 서버 전송을 시도합니다. 운영체제의 강제 종료에서는 종료 이벤트와 통신 완료가 보장되지 않으므로 주기 저장과 다음 접속의 미전송 복구를 함께 사용합니다.
- 연결 복구·화면 복귀 시 즉시 동기화를 시도하고, 일반 통신 실패는 5/10/20/40/60초 간격으로 재시도합니다. 요청 중에는 자동 저장 요청을 계속 쌓지 않습니다.
- 게임 화면에는 저장 상태 문구를 표시하지 않습니다. 설정의 저장 화면에서 저장 상태, 마지막 기기 저장 시각, 서버 저장 확인 시각과 ‘지금 저장’을 제공합니다. 서버 확인 시각은 해당 기기에서 응답을 확인한 시각입니다.
- 서버 저장이 성공한 뒤 기기 메타데이터 기록만 실패한 경우 서버 리비전을 되돌리지 않습니다. 계정이 바뀐 뒤 도착한 이전 계정의 저장 응답도 현재 계정을 변경하지 못합니다.
- 일일 백업 날짜는 실제 백업을 만든 경우에만 갱신합니다. 객체 항목 순서만 달라진 같은 저장본은 변경으로 보지 않습니다.

## 모바일 저장 보완 검증 (2026-10-04)

- 로컬 저장 및 실제 앱의 복구/전송 함수를 실행하는 자동 검사 20개 통과: 미전송 복구, 통신 실패 후 재시도, 느린 요청 중 추가 플레이, 계정 전환, 저장 공간 부족, 구버전 형식 호환 등을 확인합니다.
- 서버 단위 검사 3개와 데모 Firebase 에뮬레이터 통합 검사를 통과했습니다. 일일 백업 회귀 검사에서 같은 본문 저장 후 다음 변경 시 백업이 생성되는 것을 확인했습니다. 에뮬레이터는 로컬 Node 24에서 실행했으며 운영 설정 Node 22와의 차이는 남아 있습니다.
- 모바일 크기(390×844)의 브라우저에서 저장 표시·수동 저장·게스트 진행도 변경 후 재실행 복구를 확인했습니다. 이 검사는 Android 실기기 검사와 별개입니다.
- 타입 검사, 웹 빌드, Android Capacitor 동기화를 완료했습니다. 기존 큰 번들 경고는 남아 있습니다. APK/AAB 생성, 실기기 검사, 운영 배포는 수행하지 않았습니다.
- 계정의 최초 실행은 인터넷 연결과 서버 확인이 필요합니다. 이미 불러온 세션에서 일시적으로 끊긴 경우 기기에 보관합니다.
- 이번 보완은 저장·복구 범위입니다. 앞서 점검한 업적/랭킹 권한 우회, App Check, 외부 CSS 의존성 등은 별도 후속 작업이며 해결됐다고 간주하지 않습니다.

## 소식·커뮤니티

설정 → 소식·커뮤니티에서 공지사항, 업데이트, 디스코드, 네이버 카페를 확인합니다.

- 공지·업데이트 본문: `config/community.ts`의 `NEWS`에 추가합니다. 현재 앱에 포함되는 정적 콘텐츠이므로 변경 후 웹 배포 또는 Android 새 빌드가 필요합니다.
- 디스코드 기본 초대 링크: `https://discord.gg/QRWusRP6`. 빌드 환경의 `VITE_DISCORD_URL`로 변경할 수 있습니다.
- 네이버 카페 기본 주소: `https://cafe.naver.com/koiworld`. 빌드 환경의 `VITE_NAVER_CAFE_URL`로 변경할 수 있습니다.
- 주소가 없거나 유효한 HTTPS 주소가 아니면 준비 중으로 표시하며 외부 페이지를 열지 않습니다.

## 검사와 배포 순서

```powershell
npm run test:save
npm run typecheck
npm test --prefix functions
npm run build
$env:GCLOUD_PROJECT = 'demo-koiworld-save-review'
firebase emulators:exec --only 'auth,firestore,functions' --project demo-koiworld-save-review 'node functions/integration/account-state.emulator.mjs'
```

운영 반영은 서버 Functions를 먼저 배포한 뒤 웹/Android 클라이언트를 배포합니다. 새 클라이언트의 빈 계정 복구는 서버의 `canInitializeGameState` 응답을 사용합니다. Firestore Rules의 권한은 변경하지 않았습니다.

Android 배포 시 `npm run cap:sync` 이후 release AAB를 생성합니다. 실제 Play Games 계정으로 네트워크 단절 → 플레이 → 재실행 → 재연결, 두 기기의 저장 충돌, 앱 재설치 후 복구를 내부 테스트에서 확인해야 합니다.
