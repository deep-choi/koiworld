# Supabase Manual Test Checklist

이 체크리스트는 Supabase SQL 적용과 Google OAuth 설정이 끝난 뒤, 실제 앱에서 최소한 확인해야 할 흐름을 정리합니다.

## 사전 조건

- `supabase/migrations/20260408_000001_initial_schema.sql` 적용 완료
- Supabase Auth의 Google provider 설정 완료
- 루트 `.env`에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 설정 완료
- `npm run build` 또는 `npm run dev`가 정상 동작

## 1. 로그인

- 앱 첫 진입 시 로그인 모달이 열린다
- Google 로그인 후 앱으로 정상 복귀한다
- 새 계정이면 `profiles`, `game_states` 기본 행이 생성된다
- 상단 프로필 버튼에 사용자 이미지 또는 닉네임 기반 상태가 반영된다

## 2. 기본 저장/불러오기

- 로그인 후 연못 상태를 조금 바꾼다
- 5초 이상 기다린 뒤 새로고침한다
- 로컬 저장과 클라우드 저장이 모두 유지된다
- 다른 브라우저 세션에서도 저장된 상태를 읽을 수 있다

## 3. 프로필 / 닉네임

- 계정 모달에서 닉네임을 변경한다
- 새로고침 후 닉네임이 유지된다
- 장터 등록자 이름, 랭킹 이름에도 같은 닉네임이 반영된다

## 4. AP 표시 / 광고 보상

- 로그인 직후 AP가 0이 아닌 기대값으로 보인다
- 광고 보상 1회를 완료한다
- AP가 즉시 증가한다
- 새로고침 후에도 증가분이 유지된다
- 같은 검증 토큰으로 중복 지급되지 않는다

## 5. 새 게임 / 초기화

- 새 게임 실행 시 연못, 아이템, 점수가 초기 상태로 돌아간다
- AP 초기값이 의도한 값으로 맞춰진다
- 새로고침 후 초기화 상태가 유지된다

## 6. 장터 등록

- 코이 1마리를 장터에 등록한다
- 등록 직후 내 연못에서 해당 코이가 사라진다
- 장터 목록에 새 매물이 보인다
- 등록 수수료가 즉시 반영된다

## 7. 장터 구매 / 취소

- 다른 계정으로 같은 매물을 즉시구매한다
- 구매자 AP가 줄고, 판매자는 보상이 반영된다
- 매물 상태가 `sold`로 바뀐다
- 구매자 계정에서 코이 수령 알림이 뜬다
- 무입찰 매물은 판매자가 취소할 수 있다
- 취소 후 판매자 연못으로 코이가 다시 들어온다

## 8. 코이 수령

- 구매 또는 취소 후 `pending_koi_claims` 기반 수령이 한 번만 처리된다
- 같은 코이가 중복으로 연못에 들어오지 않는다
- 수령 뒤 새로고침해도 상태가 유지된다

## 9. 랭킹 / 업적

- 랭킹 모달이 열린다
- 명예 포인트 기준 정렬이 동작한다
- 업적 포인트 기준 정렬이 동작한다
- 업적 달성 후 포인트가 랭킹에 반영된다

## 10. 실시간성

- 두 브라우저에서 같은 계정으로 접속했을 때 세션 충돌 모달이 뜬다
- 다른 계정에서 장터 등록 또는 구매 시 목록이 새로고침 없이 갱신된다

## 확인 중 이상이 나오면 먼저 볼 곳

- 브라우저 콘솔 에러
- Supabase Auth 로그
- Supabase SQL Editor에서 테이블, 함수 생성 여부
- `services/supabase.ts`의 RPC 이름과 SQL 함수 이름 일치 여부
