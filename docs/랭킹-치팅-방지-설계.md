# 랭킹 치팅 방지 설계

## 이번 변경의 목적

클라이언트가 `rankings/{uid}`에 점수 숫자를 직접 쓰는 경로를 제거하고, 랭킹 합계를 서버가 소유하도록 변경했습니다.

## 서버가 소유하는 데이터

- `rankingState/{uid}`: 명예 트로피 점수, 업적 점수, 서버에서 수령한 업적 ID
- `rankings/{uid}`: 다른 사용자에게 공개되는 랭킹 표시용 문서
- `rankingEvents/{uid}_{eventId}`: 중복 호출 방지용 이벤트 기록

Firestore Rules에서 랭킹·랭킹 상태·랭킹 이벤트의 클라이언트 쓰기는 모두 거부합니다. 일반 `users/{uid}` 저장에서도 `honorPoints`, `achievementPoints`, 업적 수령 목록은 기존 값과 다르게 쓸 수 없습니다.

## 서버 함수로 처리하는 이벤트

- `purchaseHonorTrophies`: 서버 트랜잭션에서 저장된 젠 포인트를 확인하고 트로피·점수·잔액을 함께 변경합니다.
- `claimAchievement`: 서버가 현재 클라우드 게임 상태에서 업적 조건을 확인하고, 보상 점수·옥수수·수령 목록을 한 번에 변경합니다.
- `initializeRankingProfile`, `updateRankingProfile`: 공개 프로필을 서버 소유 랭킹 문서에 반영합니다.
- `deleteAccountData`: 계정 삭제 시 서버 소유 랭킹 데이터도 함께 삭제합니다.

모든 점수 변경 함수에는 인증 확인과 이벤트 ID 중복 방지가 포함되어 있습니다. 클라이언트는 최종 점수나 보상량을 전달하지 않고, 서버 응답을 화면에 반영합니다.

## 남은 보안 경계

현재 일반 게임 상태의 연못·코이·젠 포인트 저장은 여전히 클라이언트 게임 루프에서 발생합니다. 따라서 완전한 경쟁형 안티치트는 모든 재화 획득·소비와 코이 생성 액션까지 서버 권한으로 옮겨야 합니다. 이번 변경은 출시 전 반드시 제거해야 하는 “랭킹 문서에 점수 숫자를 직접 주입하는 문제”를 먼저 차단한 1단계입니다.

Functions와 새 Rules를 실제 프로젝트에 배포한 뒤, Play Console 내부 테스트에서 트로피 구매·업적 수령·재로그인·계정 삭제를 검증해야 합니다.
