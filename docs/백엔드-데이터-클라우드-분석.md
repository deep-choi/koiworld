# 백엔드·데이터·클라우드 분석

## Firebase 구성

- Firebase project: `koi-garden-abcf5`
- Hosting: `firebase.json`의 사이트 `koi-garden-abcf5`
- Authentication: Google, 이메일/비밀번호, Android Play Games credential, 익명 fallback
- Firestore: 개인 게임 문서와 공개 랭킹 문서 분리

## Firestore 문서

### `users/{uid}`

로그인 사용자 본인의 데이터입니다.

- `profile.nickname`
- `profile.photoURL`
- `profile.createdAt`
- `profile.lastLogin`
- `activeDeviceId`
- `gameState`
- `honorPoints`
- `achievementPoints`
- `updatedAt`

`gameState`에는 `SavedGameState` 전체가 들어갑니다.

### `rankings/{uid}`

랭킹 화면에 필요한 최소 데이터입니다.

- `uid`
- `nickname`
- `photoURL`
- `honorPoints`
- `achievementPoints`
- `updatedAt`

랭킹 문서에는 전체 연못과 코이 데이터를 저장하지 않습니다.

## 프론트엔드 서비스

- 인증: `services/auth.ts`, `contexts/AuthContext.tsx`
- Firebase 초기화: `services/firebase.ts`
- 클라우드 진입점: `services/sync.ts`
- Firestore 변환/저장/랭킹: `services/cloudData.ts`
- 프로필: `services/profile.ts`
- 세션: `services/session.ts`
- 로컬 저장: `services/localSave.ts`
- 브라우저 중복 탭 잠금: `services/tabLock.ts`

## 저장 방식

- 로컬: `zenKoiGardenSaveData_v2`
- 클라우드: 로그인 후 상태 payload가 변경될 때 15초 주기로 저장
- 클라우드 저장은 Firestore transaction을 사용해 업적 해금/수령 목록을 합집합으로 보존
- 저장 후 랭킹 문서의 명예/업적 점수를 갱신
- Firestore listener는 사용자 게임 상태 변경을 수신

## 보안 규칙

`firestore.rules` 기준:

- `users/{uid}`는 해당 UID로 인증된 사용자만 읽기/쓰기/삭제 가능
- `rankings/{uid}`는 누구나 읽을 수 있음
- `rankings/{uid}` 쓰기는 소유자만 가능
- 랭킹 쓰기 데이터의 허용 키와 점수 타입을 규칙에서 검사

새 필드를 추가하면 저장 코드와 함께 `firestore.rules`의 허용 범위를 검토해야 합니다.

## 인증 및 세션 주의사항

- Android Play Games 인증 실패는 익명 Firebase 사용자로 fallback할 수 있습니다.
- 익명 사용자를 Play Games credential에 연결할 때는 기존 UID의 게임 데이터를 보존해야 합니다.
- 같은 브라우저의 중복 탭은 `services/tabLock.ts`가 자동 저장을 제한합니다.
- `services/session.ts`에는 기기 세션 함수가 있으므로 원격 기기 충돌 동작을 변경할 때 실제 호출 경로를 확인합니다.
- Firebase credential과 사용자 토큰을 로그로 남기지 않습니다.
