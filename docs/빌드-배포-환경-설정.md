# 빌드·배포·환경 설정

## 실행 스크립트

루트 `package.json` 기준:

```bash
npm run dev
npm run typecheck
npm run build
npm run preview
npm run cap:sync
npm run cap:open
npm run cap:run
npm run audit:release
```

- `dev`: Vite 개발 서버
- `typecheck`: TypeScript 타입 검사
- `build`: `dist` 운영 산출물 생성
- `preview`: 빌드 결과 로컬 확인
- `cap:sync`: 웹 빌드 후 Capacitor Android 프로젝트 동기화
- `cap:open`: Android Studio 프로젝트 열기
- `cap:run`: 연결된 Android 기기/에뮬레이터 실행
- `audit:release`: 운영 의존성 보안 감사

## 웹 환경

- Vite 개발 서버 기본 포트: `4000`
- `vite.config.ts`가 `GEMINI_API_KEY`를 `process.env` 값으로 주입
- `services/geminiService.ts`는 현재 게임 흐름에 연결된 활성 기능이 아닙니다.
- `index.html`에서 Service Worker를 등록합니다.
- `public/sw.js`는 Network First와 캐시 fallback을 사용합니다.
- `public/manifest.json`은 standalone PWA 메타데이터를 제공합니다.

## Android 환경

- 앱 ID: `com.zenkoigarden.game`
- Capacitor 웹 디렉터리: `dist`
- Android 프로젝트: `android/`
- Firebase Android 설정: `android/app/google-services.json`
- Play Games 인증 provider: Capacitor Firebase Authentication 설정에 포함
- Android release 버전은 `android/app/build.gradle`의 `versionCode`와 `versionName`으로 관리

업로드 키스토어는 저장소 외부에 둡니다. release 빌드에는 다음 환경 변수를 사용합니다.

- `KOIWORLD_UPLOAD_KEYSTORE`
- `KOIWORLD_UPLOAD_KEYSTORE_PASSWORD`
- `KOIWORLD_UPLOAD_KEY_PASSWORD`

키 파일, 비밀번호, 실제 인증 토큰은 Git에 커밋하지 않습니다.

Android release 검증 순서:

```bash
npm run typecheck
npm run audit:release
npm run cap:sync
cd android
gradlew.bat clean bundleRelease
```

Capacitor sync를 먼저 실행하지 않으면 Android AAB에 이전 `dist` asset이 들어갈 수 있습니다.
최종 AAB는 `android/app/build/outputs/bundle/release/app-release.aab`에서 확인하고,
Play Console 내부 테스트 트랙에서 release 서명·로그인·기존 데이터 복구를 검증합니다.

## Firebase Hosting 배포

`firebase.json` 기준:

- Hosting site: `koi-garden-abcf5`
- 배포 디렉터리: `dist`
- 모든 경로를 `/index.html`로 rewrite
- 루트/index/sw는 no-cache
- `assets/**`는 immutable 장기 캐시

일반적인 배포 순서:

```bash
npm run build
firebase deploy --only hosting --project koi-garden-abcf5
```

배포 후에는 실제 운영 도메인의 HTML과 새 asset 파일이 갱신되었는지 확인합니다.

## 레거시 설정

`vercel.json`은 이전 정적 배포 호환용 파일입니다. 현재 공식 웹 배포 기준은 Firebase Hosting입니다.
