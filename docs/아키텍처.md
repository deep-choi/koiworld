# 아키텍처

## 상위 구조
1. UI 레이어: `App.tsx`, `components/*`
2. 게임 상태 레이어: `hooks/useKoiPond.ts`, `hooks/useAchievements.ts`
3. 도메인 로직: `utils/genetics.ts`, `utils/GameEngine.ts`, `utils/achievements.ts`
4. 인프라 레이어: 인증, 저장 동기화, 세션, Firestore 래퍼
5. 백엔드: Firebase Authentication, Firestore

## 주요 데이터 흐름
1. 앱 시작: `index.tsx -> AuthProvider -> App`
2. 인증: Google 로그인 후 Firebase Auth 상태 제공
3. 초기 동기화: `App.tsx`에서 `startSession + loadUserDataOnce` 병렬 실행
4. 로컬 저장: `SAVE_GAME_KEY`에 주기 저장
5. 클라우드 저장: 로그인 시 `saveGameToCloud` 주기 저장
6. 실시간 반영: 프로필 세션 충돌과 게임 상태를 Firestore listener로 반영

## 게임 엔진 구조
- `components/Pond.tsx`가 캔버스를 생성하고 `GameEngine` 인스턴스를 관리
- `GameEngine`은 코이 엔티티 동기화, 먹이 섭취, 장식/테마/수질 상태, 물 효과를 처리
- `KoiRenderer`는 다중 세그먼트 기반 코이 체형과 정확 클릭 판정을 담당

## 상태/모듈 경계
- `types.ts`: 게임 중심 타입
- `types/online.ts`: 온라인 저장/랭킹 호환 타입
- `services/firebase.ts`: Firebase 앱/Auth/Firestore 초기화
- `services/cloudData.ts`: Firestore 저장/랭킹 어댑터

## 주의 포인트
- `App.tsx` 단일 파일 비중이 큼
- `services/geminiService.ts`는 현재 빈 파일
- `index.html`은 Tailwind CDN을 사용함
