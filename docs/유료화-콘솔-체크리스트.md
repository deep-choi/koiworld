# 유료화(인앱 결제·광고) 구조와 콘솔 체크리스트

2026-11-03 브랜치에서 추가한 유료화 기능의 동작 방식과, 코드 밖에서 직접 해야 하는 콘솔 작업을 정리했습니다.
코드 작업에는 배포, Play Console, AdMob 계정 변경이 포함되어 있지 않습니다. 아래 체크리스트를 순서대로 진행하세요.

## 1. 무엇이 바뀌었나

| 기능 | 앱(Android) | 웹(koigarden.shop) |
| --- | --- | --- |
| 특별 연못 슬롯 `pond_slot` | Google Play 결제(소모성, 계정당 최대 4개) | "앱에서 구매할 수 있어요" 안내, 산 슬롯은 같은 계정이면 그대로 적용 |
| 광고 제거 `remove_ads` | Google Play 결제(비소모성), 사면 배너 제거 | "앱에서 구매할 수 있어요" 안내(웹에는 광고 없음) |
| 연못 확장권(20,000 ZP) | 그대로 | 그대로 |
| 배너 광고 | 화면 하단 작은 배너(320x50), 광고 제거 시 사라짐 | 없음 |
| 보상형 광고 | 원할 때만: 기본 사료 30개 또는 150 ZP, 하루 5회 | 없음 |
| 전면 광고 | 넣지 않음 | 없음 |

### 결제 흐름

```
앱: Google Play 결제창 (구매에 계정 해시 obfuscatedAccountId를 붙임)
 → 앱: 구매 토큰을 Cloud Function verifyPlayPurchase로 전송 (앱은 직접 승인/소비하지 않음)
 → 서버: Google Play Developer API로 구매 확인 (결제 완료? 계정 일치? 이미 쓴 토큰?)
 → 서버: 트랜잭션으로 playPurchases/{토큰 해시}(장부)와 entitlements/{uid}(혜택) 저장
 → 서버: Play에 소비(pond_slot) 또는 승인(remove_ads)
 → 앱·웹: entitlements/{uid}를 실시간 구독 → 특별 연못 생성, 배너 제거
```

- 특별 연못은 `pond-paid-1` ~ `pond-paid-4` id로 만들어 젠 포인트 연못(`pond-1` ~ `pond-4`)과 섞이지 않습니다.
- `saveGameState`는 계정 혜택을 읽어 **새로 생기는 특별 연못**이 산 슬롯 수 이하인지 검사합니다.
  이미 저장된 연못은 혜택이 줄어도 거절하지 않아 코이를 잃지 않습니다.
- 구매 복원: 같은 계정으로 로그인하면 Firestore 혜택으로 바로 복원됩니다. 앱 시작 시 마무리되지 않은 구매와
  `remove_ads`를 Google Play에서 다시 읽어 서버에 확인하고, 상점의 "구매 복원" 버튼으로도 실행할 수 있습니다.
- 구매는 로그인 계정에서만 가능합니다(익명 계정은 재설치하면 사라지므로 구매를 묶지 않습니다).
- 슬롯 한도(4개)를 넘는 구매는 서버가 승인하지 않으며, Google Play가 3일 뒤 자동 환불합니다.

### 선택한 플러그인 (Capacitor 8 호환 확인)

| 용도 | 패키지 | 버전 | 호환 근거 |
| --- | --- | --- | --- |
| 인앱 결제 | `@capgo/native-purchases` | 8.9.6 | `peerDependencies: @capacitor/core >=8.0.0`, Play Billing Library 9.1.0, 서버 확인 전 자동 승인 끄기 지원 |
| 광고 | `@capacitor-community/admob` | 8.3.0 | 8.x가 Capacitor 8 대응판(개발 의존성 `@capacitor/core ^8.0.0`), Google UMP 동의 폼 지원 |
| 서버 인증 | `google-auth-library` | 10.9.x | `firebase-admin`이 이미 쓰는 버전, androidpublisher 범위 토큰 발급 |

RevenueCat(`@revenuecat/purchases-capacitor`)은 자체 백엔드를 거치므로 "Firebase Functions에서 Play API로 직접 확인"
요구와 맞지 않아 제외했습니다.

## 2. Play Console — 인앱 상품

- [ ] 결제 프로필(판매자 계정)과 정산 계좌를 설정합니다.
- [ ] 이번 코드로 만든 AAB를 **내부 테스트 트랙**에 올립니다. 결제 라이브러리가 들어간 빌드가 한 번 올라가야 상품을 만들 수 있습니다.
- [ ] 수익 창출 → 제품 → 인앱 상품에서 아래 두 상품을 만들고 **활성화**합니다. 제품 ID는 만든 뒤 바꿀 수 없으니 정확히 입력하세요.
  - [ ] `pond_slot` — 이름 예: "특별 연못 슬롯", 설명 예: "연못을 하나 더 받아요. 계정에 저장됩니다." 가격 결정.
  - [ ] `remove_ads` — 이름 예: "광고 제거", 설명 예: "하단 배너 광고를 없앱니다. 보상형 광고는 원할 때만 볼 수 있어요." 가격 결정.
  - Play Console에는 소모성/비소모성 설정이 따로 없습니다. 서버가 `pond_slot`은 소비, `remove_ads`는 승인만 해서 구분합니다.
  - [ ] `pond_slot`의 "여러 개 구매(멀티 수량)"는 꺼 두는 것을 권장합니다. 켜도 서버가 처리하지만, 한도를 넘는 수량은 통째로 거절됩니다.
- [ ] 설정 → 라이선스 테스트에 테스트용 Google 계정을 등록합니다(실제 청구 없이 결제 테스트).

- [ ] Cloud Functions(2세대)가 쓰는 서비스 계정 이메일을 확인합니다.
  Cloud Run → 서비스 `verifyplaypurchase` → 보안 탭. 따로 지정하지 않았다면 보통
  `1076557834310-compute@developer.gserviceaccount.com`(Compute Engine 기본 서비스 계정)입니다.
- [ ] Play Console → 사용자 및 권한 → 새 사용자 초대에 위 서비스 계정 이메일을 넣고, 앱 `com.zenkoigarden.game`에 아래 권한을 줍니다.
  - [ ] 재무 데이터, 주문, 취소 설문 응답 보기
  - [ ] 주문 및 구독 관리
- [ ] 권한이 반영되기까지 최대 하루 정도 걸릴 수 있습니다. 그 전에는 서버가 "Google Play 구매를 확인하지 못했습니다"를 돌려줍니다.

## 5. AdMob

- [ ] 광고 단위를 2개 만듭니다.

- [ ] `app-ads.txt`를 `https://koigarden.shop/app-ads.txt`에 게시하고(AdMob이 알려 주는 한 줄, `public/app-ads.txt`에 두면 Hosting에 같이 올라감),

- [ ] 개발 중에는 테스트 ID 그대로 두고, 실제 ID로 바꾼 뒤에는 AdMob의 테스트 기기 등록 후 확인하세요. 자기 광고를 직접 누르면 계정이 정지될 수 있습니다.
- [ ] 대상 연령에 만 13세 미만이 포함되면 Google Play 가족 정책을 따라야 하며, 광고 요청 설정(`tagForChildDirectedTreatment` 등)을 바꿔야 합니다. 현재 코드는 일반 연령 기준입니다.

## 7. 개인정보처리방침에 추가할 내용

- [ ] **수집 항목 추가**: 인앱 결제 기록(Google Play 주문 번호, 상품 ID, 구매 시각, 계정 식별용 해시값), 광고 식별자(광고 ID), 광고 이용 기록
- [ ] **수집 목적**: 유료 혜택 지급·복원, 중복 지급과 부정 결제 방지, 광고 제공과 광고 성과 측정
- [ ] **처리 위탁·제3자 제공**: Google LLC — Google Play 결제(결제 처리), Google AdMob(광고 제공·맞춤 광고), Firebase(데이터 저장·인증·분석)
- [ ] **국외 이전**: 위 서비스는 국외(미국 등) 서버에서 처리될 수 있음을 이전 국가·항목·방법과 함께 적습니다.
- [ ] **보관 기간**: 「전자상거래 등에서의 소비자보호에 관한 법률」에 따라 대금 결제 및 재화 공급에 관한 기록은 5년 보관.
      계정 데이터를 삭제해도 결제 기록(`playPurchases`)과 혜택(`entitlements`)은 이 기간 동안 남는다는 점을 명시합니다.
- [ ] **맞춤형 광고 거부 방법**: 기기 설정 → Google → 광고에서 광고 ID 재설정·삭제. 유럽 등 동의가 필요한 지역은 앱의 동의 화면에서 선택.
- [ ] **아동**: 만 14세 미만 이용자의 개인정보 처리 시 법정대리인 동의 방침(대상 연령에 포함되는 경우).
- [ ] **환불 안내**: Google Play 환불 정책을 따르며, 결제 후 3일 안에 적용되지 않은 구매(예: 연못 슬롯 한도 초과)는 자동 환불됨.
- [ ] 개인정보처리방침 URL을 Play Console(앱 콘텐츠 → 개인정보처리방침)과 AdMob 앱 설정에 등록합니다.

## 8. 출시 전 확인 시나리오 (내부 테스트 트랙, 라이선스 테스터)

- [ ] 로그인 계정으로 `pond_slot` 구매 → "특별 연못 1"이 생기고 Firestore `entitlements/{uid}.paidPondSlots`가 1, Play Console 주문이 소비됨으로 표시
- [ ] `remove_ads` 구매 → 하단 배너가 즉시 사라지고 게임 화면이 원래 높이로 돌아옴. 보상형 광고 버튼은 남아 있음
- [ ] 앱 삭제 → 재설치 → 같은 계정 로그인 → 특별 연못과 광고 제거가 그대로
- [ ] 같은 계정으로 koigarden.shop 로그인 → 특별 연못이 보이고, 상점의 유료 상품에는 "앱에서 구매할 수 있어요" 표시
- [ ] 결제 직후 비행기 모드로 앱 종료 → 다시 실행 → "완료되지 않았던 구매를 계정에 반영했어요" 표시

- [ ] 슬롯 4개 보유 시 구매 버튼 비활성("최대 보유량 도달")
