# 유료화(인앱 결제·광고) 구조와 콘솔 체크리스트

2026-11-03 브랜치에서 추가한 유료화 기능의 동작 방식과, 코드 밖에서 직접 해야 하는 콘솔 작업을 정리했습니다.
코드 작업에는 배포, Play Console, AdMob 계정 변경이 포함되어 있지 않습니다. 아래 체크리스트를 순서대로 진행하세요.

## 1. 무엇이 바뀌었나

| 기능 | 앱(Android) | 웹(koigarden.shop) |
| --- | --- | --- |
| 연못 확장권 `pond_slot` | Google Play 결제(소모성, 계정당 최대 4개). 연못을 늘리는 유일한 방법 | "앱에서 구매할 수 있어요" 안내, 산 연못은 같은 계정이면 그대로 적용 |
| 광고 제거 `remove_ads` | Google Play 결제(비소모성), 사면 배너와 동영상 광고가 모두 사라짐 | "앱에서 구매할 수 있어요" 안내(웹에는 광고 없음) |
| 젠 포인트(20,000 ZP) 연못 확장 | **없앰**. 예전에 ZP로 산 연못(`pond-3`, `pond-4`)은 그대로 남음 | 같음 |
| 배너 광고 | 화면 하단 작은 배너(320x50), 광고 제거 시 사라짐 | 없음 |
| 동영상 광고(AdMob 전면 광고) | 쉬는 지점에서만: 교배 뒤, 코이 판매 뒤, 화살표로 연못을 넘길 때. 앱을 켠 뒤 3분간 없음, 광고 사이 최소 5분 | 없음 |
| 보상형 광고 | **없앰** | 없음 |

### 연못 규칙

- 새 게임(새 계정·게스트)은 무료 연못 1개(`pond-1`)로 시작합니다(`utils/savedGameState.ts`의 `DEFAULT_POND_COUNT`). 연못을 늘리려면 상점의 "연못 확장권"(Google Play)을 삽니다.
- 1.0.7~1.0.8에서 받은 무료 연못 2(`pond-2`)는 그대로 남습니다. 저장본에 있으면 지우거나 숨기지 않고, 새 게임을 해도 빈 연못으로 남습니다.
- 연못이 1개뿐인 예전 저장본에 연못 2를 더 채우지 않습니다(1.0.7~1.0.8은 자동으로 채웠음).
- 연못 확장권으로 생긴 연못의 id는 `pond-paid-1` ~ `pond-paid-4`이고, 화면 이름은 지금 가진 연못 다음 번호입니다
  (연못 1개였으면 "연못 2", 연못 2를 받았던 계정이면 "연못 3", 예전에 ZP로 4개를 샀으면 "연못 5"). 이미 있는 연못의 이름은 바꾸지 않습니다.
- 새 게임을 시작해도 가진 연못 칸(예전 ZP 연못, 연못 확장권 연못)은 빈 연못으로 남습니다.

### 동영상 광고 규칙

- 언제: 하던 일이 끝난 쉬는 지점에서만 띄웁니다. 지점과 시간 값은 `config/monetization.ts`의 `VIDEO_AD_TRIGGERS`, `VIDEO_AD_LIMITS`에 있습니다.
  - 교배가 끝나고 새 코이가 나온 뒤(2초 기다림), 코이를 판 뒤(1.5초), 화살표로 다른 연못에 넘어갈 때(0.6초)
  - 연못 현황 창 안에서 교배·판매했다면 그 창을 닫은 뒤에 같은 방식으로 띄웁니다(2분이 지나면 건너뜀).
  - 기다리는 사이 화면을 누르거나 키를 누르면, 하던 일을 방해하지 않도록 이번 광고는 건너뜁니다.
- 언제 안 띄우나: 앱을 켤 때·끌 때, 앱을 켠 뒤 3분 안, 직전 광고가 끝난 뒤 5분 안, 창(상점·연못 현황 등)이 열려 있거나
  먹이를 주는 중·코이를 고른 중, 결제창·로그인 창·저장 복구 화면이 떠 있을 때, 광고 제거 계정, 웹.
- 미리 받아 둔 광고가 없으면 그 지점은 건너뜁니다(늦게 받은 광고를 나중에 갑자기 띄우지 않음). 받은 광고는 55분 뒤 새로 받습니다.
- 광고가 떠 있는 동안 배경 음악과 효과음을 멈추고, 닫히면 다시 켭니다(AdMob `Showed`·`Dismissed` 이벤트).
- 실제 길이는 AdMob이 정합니다(보통 15~30초). 전면 동영상 광고는 보통 약 5초 뒤 건너뛸 수 있습니다.
  AdMob 콘솔에서 전면 광고 단위를 동영상만 나오게 설정할 수 있습니다(5번).
- 개발용 테스트 ID는 Google 문서(https://developers.google.com/admob/android/test-ads)의 Interstitial `ca-app-pub-3940256099942544/1033173712`입니다.
  예전 문서의 "Interstitial Video" 테스트 ID(`…/8691691433`)는 지금 문서에 없어 쓰지 않았습니다. 테스트 광고는 이미지일 때도 있습니다.

### 결제 흐름

```
앱: Google Play 결제창 (구매에 계정 해시 obfuscatedAccountId를 붙임)
 → 앱: 구매 토큰을 Cloud Function verifyPlayPurchase로 전송 (앱은 직접 승인/소비하지 않음)
 → 서버: Google Play Developer API로 구매 확인 (결제 완료? 계정 일치? 이미 쓴 토큰?)
 → 서버: 트랜잭션으로 playPurchases/{토큰 해시}(장부)와 entitlements/{uid}(혜택) 저장
 → 서버: Play에 소비(pond_slot) 또는 승인(remove_ads)
 → 앱·웹: entitlements/{uid}를 실시간 구독 → 새 연못 생성, 배너·동영상 광고 끄기
```

- 연못 확장권 연못은 `pond-paid-1` ~ `pond-paid-4` id로 만들어 일반 연못(`pond-1` ~ `pond-4`)과 섞이지 않습니다.
- `saveGameState`의 연못 검사(`functions/src/saveValidation.ts`의 `pondAllowanceError`):
  - 일반 연못은 **서버에 이미 저장되어 있던 수**(최대 4개)를 넘길 수 없습니다. 단, 저장되어 있던 수가 1개 이하여도 **2개까지는 받습니다**(아래 "구버전 앱 호환").
    예전에 받은 `pond-2`와 ZP로 산 `pond-3`, `pond-4`는 이미 저장되어 있으므로 계속 받고, 2개였던 계정이 `pond-3`을 새로 넣으면 거절합니다.
  - **구버전 앱 호환**: 새 앱은 연못 1개로 시작하지만, 아직 깔려 있는 1.0.8 이하 앱은 새 계정을 연못 2개로 만들고, 연못이 1개인 저장본을 불러오면
    빈 `pond-2`를 스스로 채워 저장합니다. 이 저장이 실패하지 않도록 서버의 최소 허용 수(`functions/src/saveValidation.ts`의
    `LEGACY_CLIENT_FREE_POND_COUNT`)는 2로 두고, 새 게임 기본값(`DEFAULT_FREE_POND_COUNT`)만 1로 내렸습니다. 남는 틈은 9번을 보세요.
  - 예외: 서버에 저장본이 없는 새 계정의 첫 저장(`new-account`)은, 게스트 시절 ZP로 산 일반 연못(최대 4개)을 함께 옮길 수 있습니다. 이 예외가 없으면 그런 게스트가 가입할 때 계정 저장이 영영 실패합니다.
  - 유료 연못은 **새로 생기는 것**만 산 연못 확장권 수 이하인지 검사합니다. 이미 저장된 연못은 혜택이 줄어도 거절하지 않아 코이를 잃지 않습니다.
- 구매 복원: 같은 계정으로 로그인하면 Firestore 혜택으로 바로 복원됩니다. 앱 시작 시 마무리되지 않은 구매와
  `remove_ads`를 Google Play에서 다시 읽어 서버에 확인하고, 상점의 "구매 복원" 버튼으로도 실행할 수 있습니다.
- 구매는 로그인 계정에서만 가능합니다(익명 계정은 재설치하면 사라지므로 구매를 묶지 않습니다).
- 연못 확장권 한도(4개)를 넘는 구매는 서버가 승인하지 않으며, Google Play가 3일 뒤 자동 환불합니다.

## 2. Play Console — 인앱 상품

- [ ] 결제 프로필(판매자 계정)과 정산 계좌를 설정합니다.
- [ ] 이번 코드로 만든 AAB를 **내부 테스트 트랙**에 올립니다. 결제 라이브러리가 들어간 빌드가 한 번 올라가야 상품을 만들 수 있습니다.
- [ ] 수익 창출 → 제품 → 인앱 상품에서 아래 두 상품을 만들고 **활성화**합니다. 제품 ID는 만든 뒤 바꿀 수 없으니 정확히 입력하세요.
  - [ ] `pond_slot` — 이름 예: "연못 확장권", 설명 예: "연못을 하나 더 받아요. 계정에 저장됩니다." 가격 결정.
  - [ ] `remove_ads` — 이름 예: "광고 제거", 설명 예: "하단 배너와 동영상 광고를 모두 없앱니다." 가격 결정.
  - Play Console에는 소모성/비소모성 설정이 따로 없습니다. 서버가 `pond_slot`은 소비, `remove_ads`는 승인만 해서 구분합니다.
  - [ ] `pond_slot`의 "여러 개 구매(멀티 수량)"는 꺼 두는 것을 권장합니다. 켜도 서버가 처리하지만, 한도를 넘는 수량은 통째로 거절됩니다.
- [ ] 설정 → 라이선스 테스트에 테스트용 Google 계정을 등록합니다(실제 청구 없이 결제 테스트).

## 3. Google Cloud · Play Console — 서버 구매 확인 권한

서버 함수 `verifyPlayPurchase`가 Google Play Developer API를 부를 수 있어야 합니다.

- [ ] Google Cloud 콘솔(프로젝트 `koi-garden-abcf5`)에서 **Google Play Android Developer API**를 사용 설정합니다.
- [ ] Cloud Functions(2세대)가 쓰는 서비스 계정 이메일을 확인합니다.
  Cloud Run → 서비스 `verifyplaypurchase` → 보안 탭. 따로 지정하지 않았다면 보통
  `1076557834310-compute@developer.gserviceaccount.com`(Compute Engine 기본 서비스 계정)입니다.
- [ ] Play Console → 사용자 및 권한 → 새 사용자 초대에 위 서비스 계정 이메일을 넣고, 앱 `com.zenkoigarden.game`에 아래 권한을 줍니다.
  - [ ] 재무 데이터, 주문, 취소 설문 응답 보기
  - [ ] 주문 및 구독 관리
- [ ] 권한이 반영되기까지 최대 하루 정도 걸릴 수 있습니다. 그 전에는 서버가 "Google Play 구매를 확인하지 못했습니다"를 돌려줍니다.

## 4. 배포 (직접 실행)

- [ ] Functions와 Firestore 규칙 배포: `firebase deploy --only functions,firestore:rules --project koi-garden-abcf5`
  - 새 함수 `verifyPlayPurchase`, 바뀐 함수 `saveGameState`
  - 새 규칙: `entitlements/{uid}`는 본인 읽기만, `playPurchases`는 접근 불가
- [ ] 웹 배포: `npm run build` 후 Hosting 배포
- [ ] Android: `npm run cap:sync` 후 Android Studio에서 빌드. (이 작업 환경에는 Android SDK가 없어 Gradle 빌드는 확인하지 못했습니다.)
- [ ] **함수와 규칙을 먼저 배포한 뒤** 새 앱을 내보내세요. 옛 서버에서는 유료 연못(`pond-paid-*`)이 들어간 저장을 거절합니다.
- [ ] **구버전 앱 주의(결정 필요)**: 새 `saveGameState`는 일반 연못을 새로 늘린 저장을 거절합니다. 그런데 구버전 Android 앱(1.0.8 이하)은
      아직 20,000 ZP 연못 확장권을 팔기 때문에, 함수 배포 뒤 구버전에서 ZP로 연못을 산 계정은 그 뒤 클라우드 저장이 계속 실패하고,
      새 버전으로 업데이트해도 기기에 남은 그 저장본을 올리지 못해 "저장 데이터를 확인하지 못했습니다"에서 멈출 수 있습니다.
      웹은 함수와 같은 날 배포하고, Android 새 버전을 최대한 빨리 내보내세요. 그 사이 위험을 없애려면 함수 배포를 앱 보급 뒤로 미루거나,
      Play Console 인앱 업데이트(즉시 업데이트)로 구버전 사용을 막는 방법을 검토하세요.
- [ ] 기본 연못 1개 변경은 구버전 앱과 함께 써도 저장이 실패하지 않습니다. 1.0.8 이하 앱이 채우는 빈 연못 2는 서버가 받습니다(1번 "구버전 앱 호환", 9번).

## 5. AdMob

- [ ] AdMob에 Android 앱을 추가하고 Play 스토어 등록정보와 연결합니다.
- [ ] 광고 단위를 2개 만듭니다.
  - [ ] 배너 (앱 하단 작은 배너)
  - [ ] 전면 광고(동영상) — 광고 단위를 만들 때 광고 유형에서 **동영상만** 남기고 텍스트·이미지는 끕니다.
        실제 광고 길이는 AdMob이 정하며(보통 15~30초) 보통 약 5초 뒤 건너뛸 수 있습니다. 앱이 이미 횟수를 제한하므로
        AdMob의 게재빈도 설정은 필요하면 추가로만 씁니다(예: 시간당 최대 6회).
- [ ] 예전에 만든 보상형 광고 단위가 있다면 쓰지 않으니 보관 처리해도 됩니다.
- [ ] 개인정보 보호 및 메시지 → GDPR(유럽) 동의 메시지를 만들고 게시합니다. 앱은 필요한 지역에서만 이 동의 화면을 띄웁니다.
- [ ] `app-ads.txt`를 `https://koigarden.shop/app-ads.txt`에 게시하고(AdMob이 알려 주는 한 줄, `public/app-ads.txt`에 두면 Hosting에 같이 올라감),
      Play 스토어 등록정보의 개발자 웹사이트를 `https://koigarden.shop`으로 맞춥니다.
- [ ] 출시 빌드에서만 실제 ID를 넣습니다. 세 값은 **같은 AdMob 앱**의 값이어야 합니다.
  - `KOIWORLD_ADMOB_APP_ID=ca-app-pub-…~…` (gradle 속성 또는 환경 변수)

## 9. 알려진 한계와 후속 과제

- **환불 회수 미구현**: 환불된 구매의 혜택을 자동으로 거두지 않습니다. 필요하면 Play 실시간 개발자 알림(RTDN) 또는
  Voided Purchases API로 `playPurchases`를 찾아 `entitlements`를 다시 계산하는 함수를 추가하세요.
  (이미 만든 연못 확장권 연못은 저장 검사에서 유지되므로 코이는 사라지지 않습니다.)
- **구버전 앱의 ZP 연못**: 4번의 "구버전 앱 주의"를 보세요. 함수 배포 뒤 구버전에서 ZP로 산 연못은 서버가 받지 않습니다.
- **무료 연못 2 틈(구버전 앱 호환)**: 서버는 저장되어 있던 연못 수와 관계없이 일반 연못 2개까지 받습니다. 그래서 새 앱의 기본은 연못 1개지만,
  연못 1개 계정을 1.0.8 이하 앱으로 한 번 열거나 기기 저장을 직접 고치면 무료 `pond-2`를 얻을 수 있고, 한 번 저장되면 계속 남습니다.
  코이를 잃는 문제는 없고 무료 연못 1개 차이입니다. 구버전 앱이 거의 사라진 뒤(또는 Play Console 인앱 업데이트로 구버전을 막은 뒤)
  `LEGACY_CLIENT_FREE_POND_COUNT`를 1로 내리면 막을 수 있습니다. 이미 `pond-2`가 저장된 계정은 그 뒤에도 그대로 받습니다.
  1로 내린 뒤 구버전 앱으로 연못 1개 계정을 열면 그 앱의 클라우드 저장은 계속 실패합니다.
- **게스트 첫 저장 예외**: 저장본이 없는 새 계정의 첫 저장은 일반 연못 4개까지 받습니다(게스트 시절 ZP 연못을 옮기기 위함).
  기기 저장을 직접 고쳐 가입하면 무료 연못 3개를 더 얻을 수 있는 틈이지만, 계정마다 한 번뿐이라 위험이 작다고 보았습니다.
  막으려면 `functions/src/index.ts`의 `carriesGuestProgress`를 false로 바꾸면 되지만, 그러면 ZP 연못을 가진 게스트는 가입 저장이 실패합니다.
- **동영상 광고 시간 제한은 기기 기준**: 앱을 켠 뒤 3분, 광고 사이 5분은 앱 안의 시계로 셉니다(앱을 다시 켜면 처음부터).
- **Android 빌드 미검증**: 이 작업 환경에 Android SDK가 없어 Gradle 빌드와 실제 결제·광고 동작은 기기에서 확인해야 합니다.
- **익명 계정 구매 불가**: 로그인(Play 게임즈·Google·이메일) 후 구매할 수 있습니다.

## 10. 로컬 미리보기 (npm run dev:mock)

PC 브라우저에서 실제 Android 앱을 쓰는 것처럼 광고와 결제 흐름을 눈으로 확인하는 로컬 전용 모드입니다. 진짜 결제·광고·서버는 전혀 쓰지 않습니다.

- 실행: `npm run dev:mock` → Vite가 알려 주는 주소(기본 `http://localhost:4000/`, 4000번이 쓰이고 있으면 다음 번호)를 엽니다.
- 켜지는 조건: `config/monetizationMock.ts`의 `isMonetizationMock`(`import.meta.env.DEV && import.meta.env.MODE === 'monetization-mock'`) 한 곳뿐입니다.
  `.env` 파일로는 켜지 않습니다. `npm run build`는 DEV가 false라 미리보기 코드가 빠지고, 빌드 끝에 `scripts/check-production-build.cjs`가
  `dist`에 미리보기 문구(배지, 도구 패널, 테스트 결제 수단, 가상의 광고 앱 이름, 다리 이름 등)가 하나라도 있으면 빌드를 실패시킵니다.
- 안전 장치: 로그인 창을 그리지 않고, 오른쪽 위 프로필 버튼을 누르면 이유를 휴대폰 화면 바깥 패널에만 보여 줍니다. Firebase 인증은 메모리 전용이라
  이 브라우저의 실제 로그인을 불러오지 않으며, Firestore 쓰기·Cloud Functions·통계를 부르지 않습니다. 저장은 `zenKoiGardenSaveData_monetization-mock_v1`,
  업적은 `koi_garden_achievements_monetization-mock`, 가짜 혜택은 `koiworld:monetization-mock:entitlements`(localStorage)에만 둡니다. 실제 게스트 저장은 건드리지 않습니다.
