# 유료화(인앱 결제·광고) 구조와 콘솔 체크리스트

2026-11-03 브랜치에서 추가한 유료화 기능의 동작 방식과, 코드 밖에서 직접 해야 하는 콘솔 작업을 정리했습니다.
코드 작업에는 배포, Play Console, AdMob 계정 변경이 포함되어 있지 않습니다. 아래 체크리스트를 순서대로 진행하세요.

### 연못 규칙

무료 연못은 **신규 유저 1개, 기존 유저 2개**입니다. 저장본의 `freePondCount`(1 또는 2)가 그 게임의 무료 연못 수이고,
새 버전은 모든 저장에 이 값을 적습니다(이하 "새 형식"). 1.0.8 이하 앱의 저장에는 이 값이 없습니다("구버전 형식").

| 누구 | 어떻게 구분 | 무료 연못 |
| --- | --- | --- |
| 기존 게스트·기존 저장본 | 저장본에 `freePondCount`가 없음(1.0.8 이하가 만든 저장) | 2개. 연못이 1개뿐이면 1.0.7~1.0.8처럼 빈 연못 2를 채움 |
| 새 버전에서 처음 시작한 게임(게스트 포함) | 새 게임 저장본에 `freePondCount: 1` | 1개 |
| 기준일 전에 가입한 계정 | Firebase Auth 가입 시각 < `FREE_POND_POLICY_START` | 2개. 새 버전에서 시작한 게스트 진행도로 처음 로그인해도 2개로 올림 |
| 기준일 뒤에 가입한 계정 | 가입 시각 ≥ `FREE_POND_POLICY_START` | 1개(구버전 앱으로 가입·저장한 경우는 아래 서버 규칙대로 2개 이상도 받음) |

- 기준일 `FREE_POND_POLICY_START`: **2026-11-04 00:00 한국 시간**(`2026-11-03T15:00:00Z`). `functions/src/saveValidation.ts` 한 곳에 있고 앱과 서버가 같은 값을 씁니다.
- 이미 있는 연못(연못 2, 예전 ZP 연못, 연못 확장권 연못)은 언제나 남습니다. 지우거나 숨기지 않고, 새 게임을 해도 빈 연못으로 남습니다.
  새 게임은 무료 연못 수도 그대로 둡니다(기존 유저는 새 게임 뒤에도 2개).
- 연못 확장권으로 생긴 연못의 id는 `pond-paid-1` ~ `pond-paid-4`이고, 화면 이름은 지금 가진 연못 다음 번호입니다
  (연못 1개였으면 "연못 2", 연못 2를 가진 계정이면 "연못 3", 예전에 ZP로 4개를 샀으면 "연못 5"). 이미 있는 연못의 이름은 바꾸지 않습니다.

### 동영상 광고 규칙

- 언제: 하던 일이 끝난 쉬는 지점에서만 띄웁니다. 지점과 시간 값은 `config/monetization.ts`의 `VIDEO_AD_TRIGGERS`, `VIDEO_AD_LIMITS`에 있습니다.
  - 교배가 끝나고 새 코이가 나온 뒤(2초 기다림), 코이를 판 뒤(1.5초), 화살표로 다른 연못에 넘어갈 때(0.6초)
  - 연못 현황 창 안에서 교배·판매했다면 그 창을 닫은 뒤에 같은 방식으로 띄웁니다(2분이 지나면 건너뜀).
  - 기다리는 사이 화면을 누르거나 키를 누르면, 하던 일을 방해하지 않도록 이번 광고는 건너뜁니다.
- 언제 안 띄우나: 앱을 켤 때·끌 때, 앱을 켠 뒤 3분 안, 직전 광고가 끝난 뒤 5분 안, 창(상점·연못 현황 등)이 열려 있거나
  먹이를 주는 중·코이를 고른 중, 결제창·로그인 창·저장 복구 화면이 떠 있을 때, 광고 제거 계정, 웹.
- 미리 받아 둔 광고가 없으면 그 지점은 건너뜁니다(늦게 받은 광고를 나중에 갑자기 띄우지 않음). 받은 광고는 55분 뒤 새로 받습니다.
- 광고가 떠 있는 동안 배경 음악과 효과음을 멈추고, 닫히면 다시 켭니다(AdMob `Showed`·`Dismissed` 이벤트).
- 실제 길이는 AdMob이 정합니다(보통 15~30초). 전면 동영상 광고는 보통 약 5초 뒤 건너뛸 수 있습니다.
  AdMob 콘솔에서 전면 광고 단위를 동영상만 나오게 설정할 수 있습니다(5번).
- 개발용 테스트 ID는 Google 문서(https://developers.google.com/admob/android/test-ads)의 Interstitial `ca-app-pub-3940256099942544/1033173712`입니다.
  예전 문서의 "Interstitial Video" 테스트 ID(`…/8691691433`)는 지금 문서에 없어 쓰지 않았습니다. 테스트 광고는 이미지일 때도 있습니다.

### 결제 흐름

```
앱: Google Play 결제창 (구매에 계정 해시 obfuscatedAccountId를 붙임)
 → 앱: 구매 토큰을 Cloud Function verifyPlayPurchase로 전송 (앱은 직접 승인/소비하지 않음)
 → 서버: Google Play Developer API로 구매 확인 (결제 완료? 계정 일치? 이미 쓴 토큰?)
 → 서버: 트랜잭션으로 playPurchases/{토큰 해시}(장부)와 entitlements/{uid}(혜택) 저장
 → 서버: Play에 소비(pond_slot) 또는 승인(remove_ads)
 → 앱·웹: entitlements/{uid}를 실시간 구독 → 새 연못 생성, 배너·동영상 광고 끄기
```

- 연못 확장권 연못은 `pond-paid-1` ~ `pond-paid-4` id로 만들어 일반 연못(`pond-1` ~ `pond-4`)과 섞이지 않습니다.
- `saveGameState`의 연못 검사(`functions/src/saveValidation.ts`의 `pondAllowanceError`). 일반 연못은 계정이 **새 형식으로 저장한 적이 있는지**로 나눕니다.
  - **새 형식으로 저장한 적이 없는 계정**(구버전 앱만 쓴 계정, 아직 저장본이 없는 새 계정): 일반 연못을 **4개까지** 받습니다.
    강제 업데이트를 하지 않으므로 구버전 앱의 무료 연못 2와 예전 20,000 ZP 확장권으로 늘린 연못이 저장 실패로 멈추지 않게 하고,
    게스트 시절 진행도를 처음 가입한 계정으로 옮기는 저장과, 구버전 앱을 쓰던 기기가 새 버전으로 업데이트한 뒤 처음 올리는 저장도 받습니다.
  - **새 형식으로 한 번이라도 저장한 계정**: 일반 연못을 늘릴 수 없습니다(연못은 현금 연못 확장권으로만). 받는 수는 **이미 저장된 일반 연못 수**와
    **가입 시각 기준 무료 연못 수**(기준일 전 2개, 뒤 1개) 중 큰 값입니다. 구버전 앱으로 ZP 연못을 사거나, 구버전 앱이 신규 유저 계정에 빈 연못 2를 채운 저장은 거절됩니다.
    가입 시각은 그 차이가 결과를 바꿀 때(연못 1개 → 2개)만 Firebase Auth에서 읽고, 읽지 못하면 저장을 막지 않도록 기존 계정(2개)으로 봅니다.
  - **표시 유지**: 구버전 앱의 저장에는 `freePondCount`가 없으므로, 서버가 저장되어 있던 값을 이어 붙여 저장합니다(`keepFreePondCount`).
    그래서 새 형식으로 저장한 계정은 그 뒤 구버전 앱으로 저장해도 계속 그 계정으로 남고, 새 버전이 다시 불러와도 무료 연못 수가 바뀌지 않습니다.
  - **앱이 멈추지 않게**: 새 형식으로 저장한 계정의 기기에 구버전 앱에서 늘린 일반 연못이 든 미전송 기록이 있으면(다른 기기 업데이트 등) 서버가 그 저장을 거절합니다.
    새 버전 앱은 이때 그 기기 기록을 복구용으로 남기고 클라우드 저장본으로 계속하며 "클라우드 저장본을 불러왔어요" 안내를 띄웁니다.
  - 유료 연못은 **새로 생기는 것**만 산 연못 확장권 수 이하인지 검사합니다. 이미 저장된 연못은 혜택이 줄어도 거절하지 않아 코이를 잃지 않습니다.
- 구매 복원: 같은 계정으로 로그인하면 Firestore 혜택으로 바로 복원됩니다. 앱 시작 시 마무리되지 않은 구매와
  `remove_ads`를 Google Play에서 다시 읽어 서버에 확인하고, 상점의 "구매 복원" 버튼으로도 실행할 수 있습니다.
- 구매는 로그인 계정에서만 가능합니다(익명 계정은 재설치하면 사라지므로 구매를 묶지 않습니다).
- 연못 확장권 한도(4개)를 넘는 구매는 서버가 승인하지 않으며, Google Play가 3일 뒤 자동 환불합니다.

## 2. Play Console — 인앱 상품

- [ ] 결제 프로필(판매자 계정)과 정산 계좌를 설정합니다.
- [ ] 이번 코드로 만든 AAB를 **내부 테스트 트랙**에 올립니다. 결제 라이브러리가 들어간 빌드가 한 번 올라가야 상품을 만들 수 있습니다.
- [ ] 수익 창출 → 제품 → 인앱 상품에서 아래 두 상품을 만들고 **활성화**합니다. 제품 ID는 만든 뒤 바꿀 수 없으니 정확히 입력하세요.
  - [ ] `pond_slot` — 이름 예: "연못 확장권", 설명 예: "연못을 하나 더 받아요. 계정에 저장됩니다." 가격 **₩1,900**(기본 가격을 원화로 넣고, 다른 국가는 Play Console 자동 환산을 확인).
  - [ ] `remove_ads` — 이름 예: "광고 제거", 설명 예: "하단 배너와 동영상 광고를 모두 없앱니다." 가격 **₩2,500**.
  - 앱은 가격을 Google Play에서 읽어 보여 주므로 코드에는 가격이 없습니다(로컬 미리보기의 예시 가격만 같은 값으로 맞춰 둠).
  - Play Console에는 소모성/비소모성 설정이 따로 없습니다. 서버가 `pond_slot`은 소비, `remove_ads`는 승인만 해서 구분합니다.
  - [ ] `pond_slot`의 "여러 개 구매(멀티 수량)"는 꺼 두는 것을 권장합니다. 켜도 서버가 처리하지만, 한도를 넘는 수량은 통째로 거절됩니다.
- [ ] 설정 → 라이선스 테스트에 테스트용 Google 계정을 등록합니다(실제 청구 없이 결제 테스트).

- **새 형식으로 저장하기 전의 계정은 일반 연못 4개까지 믿고 받음**: 강제 업데이트를 하지 않으므로, 새 버전으로 한 번도 저장하지 않은 계정
  (구버전 앱만 쓴 계정, 아직 저장본이 없는 새 계정의 첫 저장)은 일반 연못 4개까지 받습니다. 서버는 ZP를 실제로 썼는지 확인하지 않으므로
  구버전 앱이나 직접 고친 저장으로 무료 연못을 더 얻을 수 있고, 새 버전으로 처음 가입하는 계정도 첫 저장 한 번은 같은 틈이 있습니다
  (게스트 시절 진행도와 구버전 앱의 ZP 연못을 옮기려면 필요합니다). 첫 새 형식 저장 뒤에는 막힙니다.
  기준일 뒤 구버전 앱으로 가입한 드문 신규 유저도 이 규칙으로 무료 연못 2개(그리고 ZP 연못)를 갖게 됩니다.
- **새 버전으로 저장한 뒤 다시 구버전 앱을 쓰는 경우**: 그 계정은 일반 연못을 늘릴 수 없으므로, 다른 기기의 구버전 앱에서 ZP 연못을 사거나(기존 유저),
  1.0.8이 연못이 1개뿐인 신규 유저 저장에 빈 연못 2를 채우면 그 구버전 앱의 클라우드 저장이 계속 실패합니다.
  그 기기의 그 뒤 진행(그 ZP 연못과 ZP 포함)은 클라우드에 올라가지 않고, 새 버전으로 업데이트하면 복구용 기록으로만 남습니다.
  신규 유저라도 연못 확장권 연못이 있으면(연못이 2개 이상) 1.0.8이 연못 2를 채우지 않아 이 문제가 없습니다.
- **가입 시각을 읽지 못할 때**: Firebase Auth 조회가 실패하면 저장을 막지 않도록 기존 계정(무료 2개)으로 봅니다. 그 순간 신규 유저가 연못 2를 얻을 수 있는 작은 틈입니다.
- **게스트는 서버 검사가 없음**: 게스트 저장은 기기에만 있어 무료 연못 수를 고칠 수 있습니다. 가입할 때는 위의 "첫 저장" 규칙(4개까지)을 따릅니다.
- **계정 데이터 삭제**: 계정 메뉴에서 게임 데이터를 지우면 새 형식 저장 표시도 함께 지워져 다음 저장이 "첫 저장"이 됩니다(진행도를 모두 잃는 대가라 위험은 작음).
- **다른 로그인 방법으로 새 계정을 만들면 신규 유저**: 기준일은 계정(uid)마다 가입 시각으로 봅니다. 기존 유저가 기준일 뒤 다른 로그인 방법으로 새 계정을 만들면,
  예전 게스트 저장을 옮기는 경우가 아니면 무료 연못 1개입니다.
- **동영상 광고 시간 제한은 기기 기준**: 앱을 켠 뒤 3분, 광고 사이 5분은 앱 안의 시계로 셉니다(앱을 다시 켜면 처음부터).
- **Android 빌드 미검증**: 이 작업 환경에 Android SDK가 없어 Gradle 빌드와 실제 결제·광고 동작은 기기에서 확인해야 합니다.
- **익명 계정 구매 불가**: 로그인(Play 게임즈·Google·이메일) 후 구매할 수 있습니다.

## 10. 로컬 미리보기 (npm run dev:mock)

PC 브라우저에서 실제 Android 앱을 쓰는 것처럼 광고와 결제 흐름을 눈으로 확인하는 로컬 전용 모드입니다. 진짜 결제·광고·서버는 전혀 쓰지 않습니다.

- 실행: `npm run dev:mock` → Vite가 알려 주는 주소(기본 `http://localhost:4000/`, 4000번이 쓰이고 있으면 다음 번호)를 엽니다.
- 켜지는 조건: `config/monetizationMock.ts`의 `isMonetizationMock`(`import.meta.env.DEV && import.meta.env.MODE === 'monetization-mock'`) 한 곳뿐입니다.
  `.env` 파일로는 켜지 않습니다. `npm run build`는 DEV가 false라 미리보기 코드가 빠지고, 빌드 끝에 `scripts/check-production-build.cjs`가
  `dist`에 미리보기 문구(배지, 도구 패널, 테스트 결제 수단, 가상의 광고 앱 이름, 다리 이름 등)가 하나라도 있으면 빌드를 실패시킵니다.
- 안전 장치: 로그인 창을 그리지 않고, 오른쪽 위 프로필 버튼을 누르면 이유를 휴대폰 화면 바깥 패널에만 보여 줍니다. Firebase 인증은 메모리 전용이라
  이 브라우저의 실제 로그인을 불러오지 않으며, Firestore 쓰기·Cloud Functions·통계를 부르지 않습니다. 저장은 `zenKoiGardenSaveData_monetization-mock_v1`,
  업적은 `koi_garden_achievements_monetization-mock`, 가짜 혜택은 `koiworld:monetization-mock:entitlements`(localStorage)에만 둡니다. 실제 게스트 저장은 건드리지 않습니다.

### 화면 배치

- **데스크톱 브라우저**(폭 760px 이상, 높이 560px 이상): 가운데에 세로 휴대폰(화면 412×915, 상태 표시줄·카메라 구멍·제스처 막대·둥근 기기 테두리)이 있고,
  게임은 그 안의 iframe(`?mock-screen=1`)에서 돌아갑니다. iframe 폭이 412px이라 게임은 실제 휴대폰과 같은 모바일 배치로 나옵니다.
  창 높이가 낮으면 휴대폰 전체를 줄여서 보여 줍니다. 오른쪽 옆에 "미리보기 모드 · 실제 청구 없음" 배지와 미리보기 도구 패널이 있습니다.
- **휴대폰 크기 브라우저**(또는 개발자 도구의 기기 화면): 테두리 없이 전체 화면 게임이고, 왼쪽 아래 구석의 작은 렌치 버튼 하나로 같은 도구 패널을 펼칩니다.
- 브라우저 크기가 두 배치의 경계를 넘으면 페이지를 새로 고쳐 알맞은 배치로 다시 엽니다(진행은 미리보기 저장 칸에 남음).
- 휴대폰 화면 안에는 실제 앱에 있는 것만 나옵니다: 아래 320×50 테스트 배너("Test Ad"), 전면 동영상 광고, Google Play 결제 시트.
  미리보기에서는 개발자 패널(유전자 디버그)과 FPS 표시를 숨깁니다.
- 광고는 가상의 퍼즐 앱("Sample App")이며 외부 동영상이나 실제 광고 소재를 쓰지 않습니다(CSS·캔버스 애니메이션).
- 결제 시트에는 Google Play 라이선스 테스터에게 실제로 보이는 "테스트 주문입니다. 요금이 청구되지 않습니다." 문구를 그대로 두었습니다.
